# Случайные координаты Москвы

100 случайных точек в границах Москвы на карте, круговая диаграмма их распределения
по административным округам и управление показом точек через клик по сектору.

```bash
npm install
npm run dev
```

Ключи API не нужны, интернет нужен только для тайлов карты.

| Команда | Что делает |
| --- | --- |
| `npm run dev` | Дев-сервер |
| `npm run build` | Прод-сборка (включает `type-check`) |
| `npm run type-check` | `vue-tsc` |
| `npm run lint` | oxlint + ESLint |
| `npm run format` | Prettier |

## Стек

| | Роль | Почему |
| --- | --- | --- |
| Vue 3 + TypeScript | основа | `<script setup>`, strict |
| Vite | сборка | дефолт `create-vue` |
| Pinia | состояние | штатный стор Vue |
| amCharts 5 | круговая диаграмма | события на секторах и анимация переходов из коробки |
| MapLibre GL + OSM | карта | рендер в WebGL, растровые тайлы OSM, без API-ключа |
| Golos Text (`@fontsource-variable`) | шрифт | рисован Paratype для русского текста; self-host из npm, без CDN и внешних запросов |

Точки на карте — это GeoJSON-источник и слой `circle`, то есть настоящий WebGL-рендер,
а не 100 DOM-маркеров. Поэтому скрытие округа — один вызов `setFilter`, без пересоздания
объектов.

## Архитектура

```
src/domain/       чистый TypeScript: ни Vue, ни карты, ни графиков
  geo.ts          ray casting, bbox, равновеликая выборка
  okrugs.ts       findOkrug(), цвета, границы
  generator.ts    generateMoscowPoints()
src/stores/       Pinia
src/composables/  мост между реактивным стором и императивными библиотеками
src/components/   вёрстка
```

Генерация точек и определение округа целиком лежат в `domain/` и не зависят от UI —
их можно читать и проверять отдельно от карты и диаграммы.

Стор делится ровно на данные и представление:

```ts
points: MoscowPoint[]          // что сгенерировано
hiddenOkrugs: Set<OkrugCode>   // что скрыто

distribution  // по ВСЕМ points — кормит диаграмму
visibleCount  // минус скрытые — кормит счётчик
```

`hiddenOkrugs` не участвует в вычислении `distribution`. Это не соглашение, а структура:
пропорции диаграммы физически не могут поехать от фильтрации.

Инстансы `Map` и amCharts `Root` намеренно лежат в обычных переменных, а не в `ref`.
Reactive-прокси на дерево amCharts из тысяч объектов ломает библиотеку и стоит дорого.

## Принятые решения

**Москва — это все 12 округов, включая ТиНАО и Зеленоград.** Точки распределяются
равномерно по площади, а Троицкий и Новомосковский округа — больше половины города.
Отсюда перекос диаграммы (ТАО+НАО ≈ 55%, ЦАО ≈ 2%): это не дефект, а факт о городе, и он
же виден на карте по сгущению точек на юго-западе. Ограничение «старой» Москвой внутри МКАД
дало бы диаграмму покрасивее, но перестало бы отвечать на вопрос «случайная точка Москвы».

**Диаграмма не пересчитывается при скрытии округа.** Диаграмма и карта отвечают на разные
вопросы: **диаграмма показывает, что сгенерировано, карта — что показано**. Если бы сектор
исчезал, а остальные росли до 100%, диаграмма перестала бы описывать сгенерированный набор,
и вернуть скрытое было бы нечем — сектора, по которому кликать, больше нет. Поэтому скрытый
сектор гаснет до 15% непрозрачности, сохраняя размер и цветную обводку.

**Фильтр переживает перегенерацию.** Скрытые округа — настройка вида, а не данные.

**Легенда кликабельна наравне с секторами.** ЦАО занимает ~2% круга, попасть в него мышью
тяжело; легенда — второй вход в ту же функцию, а не отдельная фича.

**Генерация — rejection sampling.** Броски равномерны по площади bbox Москвы, попадание
~32% (~310 бросков на 100 точек, ~20 мс). `findOkrug()` возвращает округ или `null`, то есть
проверка «внутри Москвы» и определение округа — один вызов, второго прохода по данным нет.

Широта берётся не равномерно, а через `asin`: меридианы сходятся к полюсу, и равномерный
`lat` сгущал бы точки к северу примерно на 2%.

Ray casting написан вручную (~20 строк) вместо `@turf/*`: правило even-odd само
обрабатывает и MultiPolygon, и дырки, а тянуть зависимость ради одной функции незачем.

## Данные о границах

`src/assets/moscow-okrugs.geojson` — 12 полигонов АО из OpenStreetMap (`admin_level=5`),
упрощённые до 84 КБ.

Это входные данные, а не результат: в файле лежат только **контуры границ**, случайные
точки генерируются в рантайме (`Math.random()`, rejection sampling) и ни одна из файла не
берётся. Без границ задача не решается в принципе: «в пределах Москвы» (п. 1) и
распределение по округам (п. 3) требуют полигонов. Файл закоммичен, а не запрашивается на
лету осознанно: границы города — константа, а Overpass медленный, с rate-limit'ами и
периодически недоступен — проверка задания не должна зависеть от чужого API.

Зеленоградский АО — эксклав, и запрос «округа внутри площади Москвы» его не находит,
поэтому округа запрашиваются по ID отношений:

```bash
# 1. выгрузка
#   запрос okrugs.overpassql:
#     [out:json][timeout:180];
#     rel(id:2162196,162903,1252558,1320234,1278703,1282181,1304596,226149,446092,1320358,2263058,2263059);
#     out geom;
curl --data-binary @okrugs.overpassql https://overpass-api.de/api/interpreter -o raw.json

# 2. сборка ways в замкнутые кольца
npx osmtogeojson raw.json > full.geojson

# 3. упрощение
npx mapshaper full.geojson -filter-fields ref,name -simplify 20% keep-shapes \
  -o precision=0.000001 format=geojson moscow-okrugs.geojson
```

Проверка данных: суммарная площадь полигонов — 2551 км² против официальных 2561 км²
(расхождение 0.4%). Упрощение до 20% меняет площадь на 0.05%, то есть на порядки меньше
статистического шума при n=100.

## Палитра

12 оттенков, равномерно разведённых по кругу OKLCH при одинаковой светлоте. Порядок слотов
подобран поиском так, чтобы максимизировать минимальное различие соседних секторов: те же
цвета в порядке по оттенку дают ΔE 5.9 при симуляции дейтеранопии, выбранный порядок даёт
12.5 (цель 8) и 17.0 при обычном зрении (порог 15); контраст к фону у всех 12 ≥ 3:1.

Отсюда следует: **сектора нельзя пересортировывать по величине** — порядок и есть механизм
различимости. `OKRUG_ORDER` фиксирует и порядок, и цвета.

Favicon и знак в хедере — то же кольцо: 12 дуг в цветах палитры в порядке `OKRUG_ORDER`.

Оговорка: 12 категорий — это за пределами того, что цвет способен нести в одиночку. Здесь
он и не несёт: на карте округ задан положением точки внутри нарисованной границы, в легенде
и подсказках — названием. Цвет связывает диаграмму с картой, но ничего не кодирует
единолично.

## Известные ограничения

- Тайлы OSM берутся с `tile.openstreetmap.org` — годится для демо, для продакшена нужен
  свой источник тайлов.
- Логотип amCharts на диаграмме остаётся намеренно: бесплатная версия распространяется по
  linkware-лицензии, и его удаление нарушило бы условия.
